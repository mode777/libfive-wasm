# JS/TS API design

The public surface of the `libfive-wasm` package — locked baseline (AD-003,
AD-005–AD-007, AD-009–AD-011, AD-017–AD-018). Naming is camelCase; the raw
C surface keeps C names verbatim under `libfive.raw`.

Everything below assumes:

```ts
import { init } from 'libfive-wasm';
const libfive = await init();        // browser or Node — same call
```

## Entry point: `init`

```ts
interface InitOptions {
  /** Provide the wasm bytes yourself (ArrayBuffer / TypedArray). */
  wasmBinary?: ArrayBufferView | ArrayBuffer;
  /** Custom resolution of the .wasm URL (default: import.meta.url-based). */
  locateWasm?: (filename: string) => string | URL;
  /** Enable lifecycle diagnostics (leaked-object warnings). Default false. */
  debug?: boolean;
}
function init(options?: InitOptions): Promise<Libfive>;
```

Default resolution is `new URL('./libfive.wasm', import.meta.url)` — works
natively in browsers, Node ≥ 18, and is understood by Vite/webpack/Rollup
(see `packaging.md`). Each `init()` call creates an independent module
instance with its own wasm heap; pass one instance around your app.

## Core types

```ts
/** Anything that can act as a scalar in a tree expression. */
type TFloat = number | Shape;
/** Tree-or-number vectors: components may each be number | Shape. */
type Vec2Arg = [TFloat, TFloat];
type Vec3Arg = [TFloat, TFloat, TFloat];
/** Axis-aligned region: min/max corners. */
interface Region3 { min: Vec3Arg; max: Vec3Arg; }
```

Coercion rule (mirrors Python's `Shape.wrap`): wherever a `TFloat` is
expected, a plain `number` becomes a constant tree automatically.

## `Shape`

Wraps a `libfive_tree`. Construction:

```ts
libfive.x(); libfive.y(); libfive.z();     // coordinate shapes
libfive.constant(1.5);                     // constant tree
libfive.var();                             // free variable (evaluator workflow)
```

### Arithmetic & math methods

Tree-building equivalents of the Python bindings' operator overloads, plus
the full unary/binary opcode table (opcode names verbatim from
`libfive_opcode_enum`). All accept `TFloat`, all return a new `Shape`:

- Binary: `add`, `sub`, `mul`, `min`, `max`, `div`, `atan2`, `mod`,
  `compare`, `nthRoot`
- Unary: `abs`, `square`, `sqrt`, `sin`, `cos`, `tan`, `asin`, `acos`,
  `atan`, `exp`, `log`, `neg`

```ts
const blob = libfive.x().square()
  .add(libfive.y().square())
  .add(libfive.z().square())
  .sub(1);                                  // unit sphere, by hand
```

(The exact opcode-method list is finalized from the pinned commit's opcode
table during the bindings change; anything not listed is reachable through
`libfive.raw` + `Shape.fromTree`.)

### Transform methods (stdlib transforms section)

`move(offset)`, `rotateX/rotateY/rotateZ(angle, center?)` (alias
`rotate`), `reflectX/reflectY/reflectZ(x0?)`, `reflectXY/reflectYZ/reflectXZ()`,
`symmetricX/Y/Z()`, `scaleX/scaleY/scaleZ(s, o?)`, `scaleXYZ(s, center?)`,
`taperXY(base, h, scale, baseScale?)`, `taperXyZ(…)`, `shearXY(base, height,
offset, baseOffset?)`, `repel(locus, r, exaggerate?)` (+ axis/plane variants
`repelX/…/repelXy/…`), `attract(…)` (+ variants), `revolveY(x0?)`,
`twirlX/Y/Z(amount, r, center?)`, `twirlAxisX/Y/Z(…)` — camelCase mapping of
the full `transforms` section, generated alongside the stdlib (AD-017).

## Meshing

```ts
interface MeshOptions { region: Region3; res: number; }  // res ≈ half the smallest feature size
s.mesh(opts): Mesh            // via libfive_tree_render_mesh_st (AD-09: synchronous)
// convenience: s.mesh(min, max, res)

interface Mesh {
  readonly vertCount: number;
  readonly triCount: number;
  /** Zero-copy views into wasm memory; re-bound on every access (AD-006).
   *  Valid until free(); throw after. */
  get verts(): Float32Array;             // length = vertCount * 3
  get tris(): Uint32Array;               // length = triCount  * 3
  copyVerts(): Float32Array;             // JS-owned
  copyTris(): Uint32Array;
  free(): void;                          // idempotent
}
```

`res` follows libfive semantics — *approximately half the model's smallest
feature size; subdivision halts when all region sides are below it* — it is
**not** a voxel count. The docs (README + JSDoc) repeat this prominently; it
is the single most common libfive misuse.

STL export (AD-018):

```ts
exportSTL(mesh: Mesh): ArrayBuffer        // binary STL, built from views
```

## Raw bindings (AD-011)

```ts
libfive.raw.libfive_tree_render_mesh_st(tree, regionPtr, res): number;
libfive.raw.libfive_opcode_enum(name): number;
libfive.raw._malloc(size) / _free(ptr);
// … full typed C surface + shim helpers
libfive.raw.memory: WebAssembly.Memory
```

Documented as advanced/semver-minor. Never required for normal use.

## Memory rules (summary)

1. Call `free()` when done with `Shape`/`Mesh`; it's idempotent.
2. Forgetting `free()` is safe (FinalizationRegistry) but can bloat the
   wasm heap under load; `init({ debug: true })` warns on GC-driven frees.
3. Mesh views live only as long as the `Mesh`; `copyVerts()`/`copyTris()`
   or `exportSTL()` for anything kept long-term.
4. Strings returned by the kernel are copied into JS immediately and freed
   automatically — users never free strings.

## Errors

- Misuse (bad region, NaN res, wrong arity, freed object) → `LibfiveError`
  thrown before/at the boundary, message names the operation.
- Kernel failure (NULL from C where a result was required) → `LibfiveError`.
- Anything else escaping (an abort) is a bug — report it.

## Examples

Node — STL in six lines:

```ts
import { init, exportSTL } from 'libfive-wasm';
import { writeFileSync } from 'node:fs';

const libfive = await init();
const part = libfive.sphere(1).difference(libfive.box([2, 1, 1]));
const mesh = part.mesh({ min: [-2, -2, -2], max: [2, 2, 2], res: 0.02 });
writeFileSync('part.stl', Buffer.from(exportSTL(mesh)));
```

Browser — MagicaCSG-style clay:

```ts
const libfive = await init();
const blob = libfive.sphere(1, [-0.3, 0, 0])
  .blend(libfive.sphere(0.8, [0.5, 0.2, 0]), 0.4)
  .blend(libfive.cylinder(0.4, 2).rotateX(Math.PI / 2), 0.3);
const mesh = blob.mesh({ min: [-3, -3, -3], max: [3, 3, 3], res: 0.05 });
geometry.setAttribute('position', new THREE.BufferAttribute(mesh.copyVerts(), 3));
geometry.setIndex(new THREE.BufferAttribute(mesh.copyTris(), 1));
```

Worker recipe (recommended for UIs, AD-09):

```ts
// worker.ts
import { init } from 'libfive-wasm';
const libfive = await init();                    // own heap in this worker
self.onmessage = async ({ data }) => {
  const shape = buildShape(libfive, data.params); // your tree-building code
  const mesh = shape.mesh(data.region);
  self.postMessage({ verts: mesh.copyVerts(), tris: mesh.copyTris() });
  mesh.free(); shape.free();
};
```

The package works unchanged inside workers (`ENVIRONMENT=worker` is compiled
in); no bundler magic needed beyond standard worker handling.
